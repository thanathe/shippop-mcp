# The declaration helper re-words for acceptance, but never hides a dangerous good

SHIPPOP Inter customers get parcels refused at the counter because of wording, not contents: "eyeliner ×3" is refused as "liquid, cannot fly", the same parcel declared as "Cosmetics" is accepted (real case). `shippop_inter_prepare_shipment` therefore maps items to generic customs categories with HS codes — the convention SHIPPOP's own drafts use — which is accurate *and* accepted. The deliberate limit: items that are genuinely restricted for air freight (alcohol-based perfume, aerosols, lithium batteries, live plants, meat, cash) are flagged with a severity and an alternative, and the tool refuses to mark the shipment `ready_to_create` while a `block` stands. It will not pick a softer category to get them on a plane. We considered leaving that judgement entirely to the model and rejected it: mislabelling dangerous goods is an aviation-safety and legal matter and would get the user's SHIPPOP account suspended, so the guard belongs in code, not in a prompt. All Inter services are treated as air because the API exposes no transport mode and every courier quoted (Thai Post, UPS, Aramex) flies, even to LA/MM/KH.
